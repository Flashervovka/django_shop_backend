## Описание Makefile для Django‑бэкенда (Docker)

Makefile автоматизирует типовые операции с Django‑проектом, выполняемые внутри Docker‑контейнеров. Все команды используют флаг `-T` — он отключает выделение псевдо‑TTY и делает поведение команд предсказуемым в CI/CD и скриптах.

---

## Цели Makefile и их назначение

| Цель | Что делает | Зачем нужно (особенно в связке Django + Next.js) |
| --- | --- | --- |
| `make check` | Запускает `python manage.py check` внутри контейнера `django`. | Быстрая проверка системных ошибок Django (некорректные настройки, проблемы в моделях, конфликтующие приложения) без затрагивания БД. Удобно перед созданием миграций. |
| `make makemigrations` | Выполняет `python manage.py makemigrations core`. | Создаёт файлы миграций только для приложения `core` (чтобы не генерировать миграции для сторонних библиотек). Критично при изменении моделей (например, добавление поля `slug` или `image`). |
| `make migrate` | Выполняет `python manage.py migrate` внутри контейнера. | Применяет все накопленные миграции к PostgreSQL. Без этого новые поля в БД не появятся, и API/админка будут выдавать ошибки. |
| `make full-migrate` | Последовательно запускает: `check` → `makemigrations` → `migrate`. | Готовый «безопасный» сценарий для локальной разработки: сначала проверка, потом создание миграций, потом применение. Исключает запуск миграций при наличии ошибок в коде. |
| `make verify` | Выполняет `python manage.py makemigrations --check --dry-run`. | Проверка в CI: убеждается, что для всех изменений моделей созданы миграции. `--dry-run` не создаёт файлы, а только сообщает, нужны ли они. Это предотвращает случайные коммиты файлов миграций из CI. |
| `make up` | Запускает `docker compose up -d`. | Поднимает все сервисы (Django, PostgreSQL, Redis) в detached‑режиме. После этого Django доступен на `localhost:8000`, и Next.js может делать запросы к API. |
| `make down` | Выполняет `docker compose down`. | Останавливает и удаляет контейнеры (volumes сохраняются, данные не теряются). |
| `make logs` | Выполняет `docker compose logs -f django`. | Просмотр логов Django в реальном времени — ключевой инструмент отладки, когда API не стартует или падает при запросе. |
| `reset-full` | Выполняет `make down make full-migrate make up`. | Полный сброс окружения: остановка, миграции, запуск... |

## Типовые сценарии использования если make не установлен

### Локальная разработка после изменения модели (senior‑поток)

Когда ты меняешь модель (например, добавляешь поле или обновляешь `slug`-логику):

```bash
make full-migrate && make up
```
### 0.Если контейнеры не подняты
docker compose up -d

### 1. Проверка кода на ошибки
docker compose exec -T django python manage.py check

### 2. Создание миграций (только для приложения core)
docker compose exec -T django python manage.py makemigrations core

### 3. Применение миграций к базе данных
docker compose exec -T django python manage.py migrate

### 4. Пересоздание django сервиса и запуск остальных сервисов
docker compose up -d --force-recreate django
